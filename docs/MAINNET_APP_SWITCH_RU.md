# Главное приложение: Arc Mainnet 5042

`#/create` и `#/groups` по умолчанию открывают Arc Mainnet. Testnet остаётся отдельным явным выбором, а `#/demo` показывает только синтетические данные.

В `public-deployments.json` закреплены публичные факты действующего контракта: `0xe05790767da98b524472ea9d78459aca4fb3b6c6`, блок `27856267`. Read-only `node scripts/verify-mainnet-existing.mjs` подтвердил chain ID 5042, успешный creation receipt `0xd3135a28e036f0227c8b21e6c657b7e5325caa44e3d332a8cfba167c02a02b54`, деплоера `0x3B0278E623a5F9C50AfaAB22c972c69Ec687448a`, точные creation data и runtime bytecode, а также `USDC()` = `0x3600000000000000000000000000000000000000`. Скрипт не подписывает и не отправляет транзакции.

Для Vercel Production публичные переменные, если они заданы, должны быть **обеими** и совпадать с закреплёнными значениями:

```text
VITE_ATOMIC_CLOSEOUT_MAINNET=0xe05790767da98b524472ea9d78459aca4fb3b6c6
VITE_ATOMIC_DEPLOY_BLOCK_MAINNET=27856267
```

При отсутствии переменных production build использует те же публичные значения из репозитория. При неполной паре или несовпадении `npm run build` завершается ошибкой. Доступа к настройкам Vercel в локальной среде нет; владелец должен проверить Production scope и новый deployment после push.

Подключение Rabby запрашивает только доступ к аккаунту. Если кошелёк уже в сети 5042, приложение его не переключает. Если сеть другая, переключение предлагается отдельной кнопкой. Перед каждой финансовой операцией требуется подтверждение в интерфейсе, а перед симуляцией и непосредственно перед запросом подписи повторно проверяются RPC chain ID, wallet chain ID, аккаунт и точный mainnet runtime. Все реальные суммы и адреса нужно проверить в Rabby. Контракт не проходил независимый аудит.
