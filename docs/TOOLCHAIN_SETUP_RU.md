# Инструменты выпуска

## Foundry на этой Windows-машине

В архиве `.foundry-version` закреплена `v1.7.1`; реально установлен обычный Foundry `1.8.5`. Конфигурация требует Solidity `0.8.28`, EVM `cancun`, optimizer `200`. Установленный компилятор найден в `%APPDATA%\svm\0.8.28\solc-0.8.28` и успешно компилирует проект. Разница версий Foundry не вызвала отказа тестов: свежий `npm run contracts:test` завершился успешно.

Первоначальный сбой — `svm-rs` не может определить домашний каталог у ограниченного Windows-пользователя, когда Foundry ищет компилятор по версии. `scripts/run-foundry.mjs` задаёт **только процессу** `FOUNDRY_SOLC` с уже установленным официальным компилятором и проверяет версию; загрузок и изменений системных переменных нет.

`npm run contracts:build` компилирует 56 файлов, но установленный native Windows `forge build` после компиляции всё ещё падает на создании глобального кэша локальных сигнатур (`Failed to get cache_dir`). `forge test` полностью компилирует и запускает suite. Для mainnet deployment использовать поддерживаемый Arc Foundry в WSL/Linux согласно [Arc Docs](https://docs.arc.io/arc/tutorials/install-arc-foundry), заново собрать bytecode и сравнить его с audited source/ABI перед подписью. Нынешний native Foundry не считать готовым к Arc deployment.

## Bun

`.bun-version` требует `1.3.14`. Bun не найден в `PATH`, стандартной папке пользователя или workspace. Он нужен для неизменённых `bun:test` модельных тестов и оригинальных testnet-скриптов. Попытка получить пакет через npm завершилась `EACCES` на исходящем HTTPS. Не устанавливались неподтверждённые бинарники и не ослаблялись системные политики.

После восстановления разрешённого HTTPS владелец может установить закреплённую версию по [официальной инструкции Bun](https://bun.sh/docs/installation) в своей обычной PowerShell-сессии: `iex "& {$(irm https://bun.com/install.ps1)} -Version 1.3.14"`, затем проверить `bun --version`, `bun --revision`, выполнить `bun install --frozen-lockfile` и `bun test tests`. Не запускать скачанный скрипт при недоверенном источнике или если политика организации запрещает установку. Для frontend build сейчас достаточно установленного Node/npm.

## Сеть

DNS разрешает оба Arc RPC, GitHub API и npm registry. TCP `:443` ко всем четырём сразу отклонён Windows `PermissionError 10013`; до TLS/HTTP соединение не доходит. Proxy-переменные отсутствуют, системный proxy пользователя выключен. Это ограничение исходящего соединения среды, не ошибка адреса Arc RPC, DNS или сертификата. Не менять firewall/proxy в обход политики. Проверять RPC, `gh api user` и Vercel на разрешённой сети/сессии.
